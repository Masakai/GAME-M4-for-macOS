# GAME 言語の macOS ネイティブ処理系(インタプリタとコンパイラ)設計書

2026-11-07 作成。同日、§4 の決定と §11 の影響範囲の承認を得た。M1 は C、M2 は GAME-M4、M14 は当面自分の Mac だけ(署名なし)に決まった。

## 1. 目的

GAME65G(Glow65 の 6502 用 GAME インタプリタ)と同じ構文の GAME 言語を、Apple Silicon の macOS でネイティブに動かす。

- インタプリタを Swift で書く。6502 のエミュレーションは使わない。
- コンパイラを Swift で書く。GAME のプログラムを ARM64 のアセンブリに変換し、Xcode の `as`/`ld` で Mach-O の実行ファイルにする。
- GUI のアプリ(端末、エディタ、ファイルの読み書き)と CLI を作る。

Glow65 側で進めている GAME65GC(GAME で書くセルフコンパイラ、`~/Glow65/documents/designs/2026-11-07-game65g-compiler.md`)とは別物で、コードは共有しない。

| M20 | GUI の実行 | 「実行」はプログラムと変数を消してから、エディタの内容を読み込んで `#=1` で実行する。実行中なら割り込んで止めてから行う | |

## 5. GAME65G の動きのうち、仕様書にない点(asm から読み取ったもの)

ここに書く動きは、テストで固定する。

### 5.1 文と式の読み方

- 文の区切りに空白は必須ではない。STMT は文を 1 つ実行したあと、空白を飛ばして次の文字で次の文を決める。`"AB"/` は文字列のあと改行になる。
- 式は演算子を見つける限り読み続ける。`?=A/` は `/` を割り算として読み、右の項がないので ERR になる。
- 構文解析は、普通のトークナイザではなく、GAME65G の STMT、TERM、EXPR と同じ 1 文字ずつの規則で書く。インタプリタとコンパイラで同じ解析器を使う。
- 文の頭の文字が `" / ? $ . # ! ] > ; @ =` のどれでもなければ代入として読む。代入先は `A-Z`、`&`、`*`、`'`。それ以外は ERR。
- 変数名は、英字の後ろに続く英字を読み飛ばす(`ALPHA` は `A`)。
- `$` の直後が 16 進の桁なら 16 進の定数、そうでなければ 1 文字入力。`$A` は 10 である。
- `<>`、`<=`、`>=` は 2 文字の演算子。`<` `>` `=` の次の文字で決める。

### 5.2 飛び先

- `#=n` と `!=n` は、n が 0 なら何もしない。それ以外は、番号が n 以上(符号なしで比べる)の最初の行へ飛ぶ。そのような行がなければ実行を終える。
- `#=-1` は特別な扱いではない。-1 は符号なしで 65535 なので、それ以上の行がなく、終了になる。負の値と、最後の行より大きい値はすべて終了になる。
- 注釈の行(行番号の後ろが空白でない行)に飛ぶと、次の行へ進む。

### 5.3 スタック

- GOSUB、FOR、DO は同じスタックに積む。1 段に、再開の位置、そのときの行、終値を持つ。DO の終値は 0。31 段を超えると ERR。
- `]` と NEXT/UNTIL は、一番上の段の種類を見ない。空なら ERR。
- `]` と、ループの先頭へ戻る NEXT/UNTIL は、行も戻す。エラーの行番号も戻した行になる。
- FOR(`V=a,b`)は、V に a を入れてから b を終値として積む。ループの本体は少なくとも 1 回実行する。
- NEXT/UNTIL(`@=e`)は、`=` の次が変数名ならその変数に e を入れる。そのあと「終値 < e」(符号付き、オーバーフローを補正して比べる)ならループを抜け、段を捨てる。そうでなければループの先頭へ戻る。UNTIL は終値 0 なので、e が 1 以上で抜ける。

### 5.4 値

- 値はすべて 16 ビット。加減乗算は下位 16 ビットに丸める。比較は符号付き。
- 割り算は符号付きで、商は 0 に向けて切り捨てる。余り(`%`)の符号は割られる数に合わせる。0 で割ると ERR。
- `%t` は t を評価してから、直前の割り算の余りを値にする(t の中に割り算があれば、その余りになる)。
- 配列 `V(i)`、`V:i)` は、V の値を読んでから添字を評価する。添字の中で V を変えても、基準の番地は変わらない。
- 乱数は xorshift 16 ビット(シフト 7、9、8)。種が 0 なら 1 にしてから回す。`'n` は乱数を n で符号なしに割った余りに 1 を足す。n が 0 なら 0。種の初期値は `$ACE1`。
- 10 進の定数が 16 ビットを超えると、下位 16 ビットに丸める。

### 5.5 入出力

- 先打ちのキーは 64 文字の環状バッファにためる(満杯なら捨てる)。中断の確認で読んだ Ctrl-C 以外のキーをためる。`$` と行の入力は、バッファを先に読む。
- Ctrl-C で中断したときはバッファを空にする。エラーでは空にしない。
- 行の入力は 120 文字まで。Backspace(`$08`、`$7F`)で 1 文字消し、`$08`、空白、`$08` を出す。`$20` 未満の文字は無視する。
- 行の入力のあと、文字列と注釈の外の小文字を大文字にする。行番号の後ろが空白でも CR でも `/` でもなければ注釈で、変換しない。
- `?`(数値の入力)は 1 行を読み、式として評価する。実行時に式を評価するので、コンパイル後のランタイムにも式の評価器が要る。
- エラーは `ERR` と行番号、中断は `BRK` と行番号を、行の頭でなければ改行してから出す。直接実行なら行番号を付けない。
- プロンプトは、行の頭でなければ改行してから `>` を出す。

## 6. メモリの使い方

GAME65G の番地をそのまま使う(M3)。

| 範囲 | 用途 |
|---|---|
| `$0000-$002C` | 処理系の作業領域。`=` `&` `*` `'` と `%` の値は GAME65G と同じ番地(`$0A` 先頭、`$0C` 末尾、`$0E` RAM 末尾、`$10` 乱数、`$08` 余り)に置く |
| `$0080-$00B3` | 変数 A-Z(下位、上位の順) |
| `$0400-$04FF` | 行の入力のバッファ |
| `$0500-$05BF` | 第 2 スタック(インタプリタのみ。M11) |
| `$05C0-$05FF` | 先打ちのキーのバッファ |
| `$0600-$7FFF` | プログラムと、配列に使える空き |
| `$8000-$FFFF` | RAM(GAME65G では ROM。M3) |

- インタプリタは、`ACC` などの作業用の値を Swift の変数に持ち、仮想メモリには置かない。仮想メモリに置くのは、プログラムから見える値(変数、特殊レジスタ、余り、プログラム、バッファ)だけにする。
- 番地の計算は 16 ビットで回る(`$FFFF` の次は `$0000`)。

### 7.1 CLI

| 使い方 | 動作 |
|---|---|
| `gamem4` | 対話モード(プロンプト `>`) |
| `gamem4 prog.gam` | ファイルを読み込み、`#=1` で実行する |
| `gamem4 -i prog.gam` | ファイルを読み込んで対話モードに入る |
| `gamem4 compile prog.gam -o prog` | 実行ファイルを作る |
| `gamem4 compile prog.gam -S -o prog.s` | アセンブリだけを出す |

- ファイルは、端末に打ち込んだのと同じく 1 行ずつ行の入力として読む(エコーしない)。行番号のない行は直接実行になる。
- 入力が tty でなければ raw モードにしない。

### 7.2 アプリ

- 左にエディタ(`.gam` のテキスト)、右に端末。
- メニューとツールバー: New、Open…、Save、Save As…、Run(エディタの内容を `&=0` のあとに送り、`#=1` で実行)、Compile…(実行ファイルを保存)、Compile and Run(コンパイルした実行ファイルを子プロセスで動かし、入出力を端末につなぐ)、Stop(`$03` を送る)。
- 端末は 1 本の会話として、インタプリタの対話モードとつながる。コンパイルしたプログラムを動かしている間は、端末の入出力をその子プロセスにつなぎ替える。
- 端末の部分は、Glow65 の `TerminalModel.swift` を読んでから、流用するか決める。

## 8. コンパイラ

### 8.1 流れ

1. `.gam` ファイルを行の入力として読み、行のイメージ(M4)を作る。行番号のない行はコンパイル時の誤りにする。
2. 全行を構文解析し、構文木にする。注釈の行は、行の表に入れて本文は持たない。
3. ARM64 のアセンブリを出す。
4. `xcrun as` でアセンブルし、ランタイムとともに `xcrun clang`(リンクのドライバとして使う)でリンクする。arm64 の実行ファイルは `ld` が ad-hoc 署名を付ける。最初に、最小のプログラムが実際に起動することを確かめる。

### 8.2 生成するコードの約束

- 仮想メモリの先頭を x19 に固定する。変数 V は `[x19, #0x80+2*V]` で `ldrh`/`strh` する。
- 式の値は w0 に置く。比較の前に `sxth` で符号を広げる。二項演算の左の値は、右が定数か変数なら w1 に直接入れ、そうでなければスタックに退避する。
- 行の頭で、行の番号を x20 に入れ(エラーの表示に使う)、Ctrl-C の確認を呼ぶ。
- 飛び先が定数の `#=`、`!=` は、コンパイル時に行の表から飛び先を決めて `b` にする(§5.2 の規則で決める。行がなければ終了処理へ)。式なら、実行時に行の表を探す。
- 第 2 スタックはランタイムが持つ(M11)。`!=` は再開の番地を `adr` で作って積む。`]` と NEXT は積んだ番地へ `br` する。
- x18 は使わない。シンボルには `_` を付ける。番地は `adrp`/`add` と `@PAGE`/`@PAGEOFF` で取る。SP は 16 バイト境界にそろえる。

### 8.3 インタプリタと動きが変わる点

| 点 | インタプリタ | コンパイル後 |
|---|---|---|
| 構文の誤り | 実行した行で ERR | コンパイル時に止まる(M9) |
| `=式`、`==`、`&=式`、`>=式` | `>=` 以外は使える | コンパイルできない(M8) |
| Ctrl-C を調べる間隔 | 文ごと | 行の頭ごと(M7) |
| `$0500-$05BF` の内容 | 第 2 スタック | 使わない(M11) |
| 実行を始める行 | `#=n` で選べる | 常に最初の行から |
| LIST、行の追加 | できる | できない(対話モードがない) |

## 9. ランタイム

### 9.1 持つ機能

- 起動: 仮想メモリ(64KB)を確保し、行のイメージを `$0600` へ写し、特殊レジスタと種を初期化し、tty なら raw モードにする。終了時とエラーで止まるときに、端末の設定を必ず戻す。
- 出力: 1 文字、CR LF、10 進(桁指定)、16 進 2 桁、文字列。出力は `write(2)` を直接呼ぶか、毎回書き出す(パイプにつないだとき、`?` の入力の前の表示が遅れないように)。
- 入力: 先打ちのバッファ、待たない 1 文字入力(`poll` のタイムアウト 0)、行の入力(§5.5)、`?` の式の評価。
- 演算: 乗算、割り算と余り、乱数、行の表の検索、第 2 スタック。
- エラーと中断の表示。終了コードは、正常終了が 0、ERR が 1、BRK が 130。

### 9.2 `?` の式の評価

`?` で入力した行は、TERM と EXPR の規則で評価する。変数は仮想メモリにあるので、評価器は同じメモリを読み書きする。入力の中の `?` と `$` も、インタプリタと同じく動く。

### 9.3 ランタイムの言語(M1。案 B に決定)

| 案 | 内容 | 利点 | 欠点 |
|---|---|---|---|
| A | ARM64 のアセンブリで書き、コンパイラの中に文字列として持つ。生成したコードと一緒にアセンブルする | `as`/`ld` だけで完結する。選んだ出力形式の方針に合う | 式の評価器(§9.2)、行の入力、端末の設定をアセンブリで書くので、量が多い |
| B | C で書き、コンパイラの中に持つ。コンパイルのたびに clang で `.o` にしてリンクする | 書く量が少なく、読みやすい | clang が必須になる(Command Line Tools に含まれる)。「C に変換して clang」とは別だが、C のコードが入る |

どちらの案でも、生成するコードは ARM64 のアセンブリで、ランタイムを呼ぶ形になる。

### 9.4 配布(M14。当面は自分の Mac だけ)

- 自分の Mac で使うだけなら、署名なしのビルドでよい。
- Glow65 と同じく公証して配布するなら、Developer ID の署名と Hardened Runtime を付ける。App Sandbox は使えない(`xcrun` と子プロセスを使うため)。
